# Outpoll

Ключ Dune — в письме с ответом. Вставь его в `.env` как `VITE_DUNE_API_KEY`. В публичный репозиторий ключ не кладём.

Дашборд торгового оборота Kalshi и Polymarket на одной шкале USD.

## Запуск

Node.js 20.19+ или 22.12+.

```sh
cp .env.example .env
# вставь VITE_DUNE_API_KEY из письма
npm i
npm run dev
```

ID запросов Dune уже прописаны в `.env.example`. Нужен только ключ из письма. После правки `.env` перезапусти Vite.

## Откуда данные

Браузер ходит в Dune напрямую (read-only ключ виден пользователю сессии). Тянутся полные snapshots обеих платформ, фильтры и агрегации считаются локально. Успешный snapshot пишется в IndexedDB, чтобы следующий визит не ждал сеть.

Папка `server/` — не бэкенд для объёмов. Это Vite-плагин только для AI-анализа точки графика: проксирует запрос к OpenRouter, чтобы ключ не попал в бандл. Без `OPENROUTER_API_KEY` демо объёмов работает как обычно; кнопка AI при запросе показывает понятную ошибку про отсутствующий ключ.

## Доп. фичи и зачем

| Фича | Зачем |
| --- | --- |
| Фильтры периода и категорий в URL | Можно шарить ссылку и ходить «назад/вперёд» без потери контекста |
| Два режима графика: платформы и категории | Сравнение площадок и разрез по таксономии без отдельных экранов |
| Mini-chart / brush периода | Быстрый выбор произвольного окна по всей истории |
| Недельная агрегация на длинной истории | Иначе «Всё время» превращается в нечитаемый зубчатый дневной шум |
| Карточки KPI и Δ к прошлому окну | Сразу видно, кто вырос и какая доля рынка, без выгрузки в Excel |
| Таблица категорий с сортировкой и спарклайнами | Сверить вклад категорий и тренд внутри выбранного окна |
| Экспорт CSV / PNG / SVG | Отдать график или сырые ряды в отчёт |
| IndexedDB-кэш snapshots | Повторный заход и фоновое обновление не мигают пустым экраном |
| AI-анализ выбранной точки (опционально) | Короткий контекст «что случилось в этот день/неделю» со ссылками; без ключа OpenRouter остальной UI не ломается |
| Светлая / тёмная тема | Системная тема по умолчанию, ручной переключатель в шапке |

## Что будет при 10× данных

Рост в первую очередь по числу дней и строк категорий в snapshot, не по числу HTTP-запросов на фильтр.

- Загрузка. Пагинация Dune и так качает весь результат один раз. При 10× объёме вырастут время первого fetch и размер IndexedDB. Кэш по `executionId` / `calculatedAt` не смешивает половинчатые выгрузки.
- Фильтры. Смена периода и категорий не бьёт в сеть: селекторы и dashboard пересчитывают уже лежащий snapshot. Узкое место — CPU на агрегации и построении геометрии SVG, не latency API.
- График. Рисуем точки выбранного окна, не весь сырой ряд разом в DOM-событиях. На очень длинной истории помогает недельная агрегация. Подписи и hit-testing остаются O(видимых точек).
- Память. В TanStack Query и IndexedDB лежит полный snapshot на платформу. При 10× стоит следить за размером JSON и не дублировать нормализованные ряды без нужды.
- AI. В промпт уходит контекст одной точки и соседней, не весь архив. Стоимость и размер запроса от 10× истории почти не растут.
