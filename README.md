# Outpoll

Дашборд торгового оборота Kalshi и Polymarket. Общая шкала в USD, фильтры по категориям.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

Для демо с живыми данными скопируйте `.env.example` в `.env`. Укажите read-only ключ Dune и ID запросов. Оставьте `VITE_DATA_MODE=dune`. Если конфигурация Dune неверная, приложение не запускается и само на fixtures не переключается. Локальная работа без API описана в разделе «Локальные fixtures».

```sh
npm ci
npm run dev
```

## Команды

- `npm run dev` запускает сервер разработки.
- `npm run typecheck` проверяет TypeScript.
- `npm run build` проверяет типы и собирает production в `dist/`.
- `npm run preview` открывает production-сборку.
- `npm test` проверяет API-транспорт, схемы, пагинацию, snapshot-кэш, диапазоны, URL-фильтры и геометрию графика.
- `npm run fixtures:update` вручную скачивает два полных результата Dune и обновляет dev fixtures.

## Стек

React, Vite, TypeScript в режиме strict, Tailwind CSS v4 через `@tailwindcss/vite`, shadcn/ui на Base UI со стилем `base-nova`, Motion из `motion/react`.

Серверные данные запрашивает TanStack Query, пакет `@tanstack/react-query`. Общий `QueryClient` лежит в `src/shared/query-client.ts`. `QueryClientProvider` подключён в `src/main.tsx`. По умолчанию `staleTime` равен 1 минуте, `gcTime` неактивных запросов равен 30 минутам. Конкретный источник может задать другие значения. Query-кэш хранится в памяти. Полные snapshots Dune отдельно пишутся в IndexedDB через `idb`.

Запросы описывайте рядом с функцией, которой они нужны, через `queryOptions` и `useQuery`. В `queryKey` кладите все параметры запроса. В `fetch` передавайте `signal` из `queryFn`, чтобы отменять устаревшие запросы. Если новые параметры меняют `queryKey`, ставьте `placeholderData: keepPreviousData`. Тогда предыдущие данные остаются на экране, пока грузятся новые. В текущем volume dashboard диапазоны и категории считаются локально, и query keys при этом не меняются. HTTP-ошибки проверяйте явно. Ответы API проверяйте Zod на границе запроса.

## Фильтры в URL

Период, категории и вид графика записаны в URL.

- `from=YYYY-MM-DD&to=YYYY-MM-DD` задаёт точные даты.
- `range=7d|30d|90d|all` задаёт пресет. При выборе пресета интерфейс записывает точные даты.
- `categories=sports,politics,…` задаёт категории. Если параметра `categories` нет, выбраны все. `categories=` означает пустой выбор.
- `view=categories` переключает график на категории.
- `scale=symlog` задаёт шкалу графика платформ. Отдельного переключателя шкалы в UI нет.

Ссылкой можно поделиться. Кнопки «назад» и «вперёд» возвращают фильтры.

Видимость платформ и выбранную дату хранит состояние React. В `localStorage` лежат тема, последний пресет периода и архив AI-анализа. Акцент зафиксирован.

## Экран

- `src/app/app.tsx` собирает экран и объём не считает.
- `src/widgets/dashboard-header/` показывает Outpoll и переключатель светлой и тёмной темы.
- `src/widgets/trading-volume/` содержит диапазоны, легенду, SVG-графики платформ и категорий, mini-chart выбора периода, экспорт, загрузку и пустые состояния.
- `src/widgets/category-filters/` содержит кнопки категорий.
- `src/features/volume-filters/` синхронизирует URL с интерфейсом через `useSyncExternalStore`, `pushState` и `popstate`.

### График объёма

`use-volume-dashboard.ts` подписывается на два snapshot-запроса, нормализует строки, мемоизирует расчёты и собирает ошибки источников по отдельности. `volume-source-errors.tsx` показывает предупреждения над графиком и кнопку повтора для каждой платформы. `chart-model.ts` считает шкалы, разрывы линий и ближайшую дату.

Кнопки категорий сделаны на shadcn Toggle и стоят в сетке из двух колонок. Выбранные категории подсвечены и показывают известный оборот за период. В режиме категорий при наведении они показывают оборот за выбранную дату или неделю. У невыбранных категорий сумма скрыта. На небольших экранах сворачивается только блок категорий. Карточки платформ остаются на экране. Источник и метод подсчёта описаны в popover карточки платформы. Отдельного блока об источнике данных нет.

### Период

7, 30 и 90 дней считаются календарными днями UTC включительно, от последней даты в загруженной истории. Даты периода стоят над графиком.

Для истории длиннее 28 дней режим «Всё доступное» на графике группирует дни в календарные недели, с понедельника по воскресенье. Первая и последняя недели остаются на графике, даже если в них меньше семи дней. Подпись показывает фактические даты и число дней. Хвостовая неполная неделя рисуется пунктиром. При наведении тултип остаётся на последней полной неделе. Дни хвостовой недели не входят в KPI, изменение и таблицу категорий, иначе сравнение с прошлым периодом занизится.

Период графика и таблицы совпадает с выбранным диапазоном. Категории на границы периода не влияют.

Если внутри показанной недели у платформы нет хотя бы одного дня, недельная сумма считает только известные дни и помечается как неполная. На графике это пунктир и подпись «неполные данные». Пропуски нулём не считаются.

В дневном режиме календарные пропуски рисуются разрывами линий. Известные дневные суммы входят в карточки и таблицу.

На графике категорий сохраняется сумма доступных платформ. Если одна из включённых платформ не прислала данные, сумма помечается как «Известный оборот» и «Неполные данные».

История Polymarket в сохранённом результате Dune начинается 21 ноября 2022. Платформа работает с 2020 года, поэтому до этой даты линия обрывается. Подписи на графике есть только у доступных значений. Для отсутствующей платформы `aria-valuetext` сообщает «Нет данных».

Произвольный период остаётся дневным, даже если он почти покрывает всю историю.

### Загрузка и ошибки

Диапазоны и категории пересчитывают сохранённые строки локально и snapshot query keys не меняют. Фильтрация не делает новых HTTP-запросов и не убирает старый график на время загрузки. При фоновом обновлении snapshot прежние данные остаются на экране.

Если платформа не загрузилась, над графиком появляется её предупреждение и кнопка «Повторить». Если snapshot не обновился, предупреждение сообщает, что показан предыдущий снимок и данные могут быть старыми.

Повтор вызывает `refetch` только этой платформы. Кэш не очищается. Уже идущий запрос заново не стартует. Пока обновление идёт, кнопка отключена и показывает загрузку. Успешная загрузка убирает предупреждение. После повторной ошибки кнопку можно нажать снова.

Ошибка одной платформы не скрывает данные другой. Предупреждения видны при скрытых сериях и при пустом выборе категорий.

Нормализация, агрегация и геометрия мемоизированы отдельно. Движение курсора обновляет только выбранную дату.

### Анимация графика

Смена периода и категорий меняет геометрию линий и осей за 300 мс. Два графика друг на друга не накладываются. `chart-transition.ts` интерполирует экранные координаты и сохраняет вершины обеих линий и разрывы данных. При повторном переключении `use-chart-transition.ts` начинает движение от текущего кадра. Промежуточные координаты не меняют исходные данные и значения tooltip. Пустые состояния делают короткий fade и высоту блока не меняют. При reduced motion переходы мгновенные.

### Карточки платформ

На десктопе карточки Polymarket и Kalshi стоят справа от графика. На небольших экранах они стоят над ним. В карточке компактная сумма за выбранные категории и период, доля общего оборота с полоской и изменение к предыдущим 7, 30 или 90 календарным дням UTC. Точная сумма лежит в атрибуте `title`. Источник и метод подсчёта лежат в подсказке.

`summary.ts` суммирует доступные дневные значения за выбранный период. При недельной агрегации графика хвостовая неполная неделя не входит в KPI и изменение. Карточки и строка итога выбранных категорий используют одни и те же дни. Неполные суммы помечаются.

Доли показываются, когда обе платформы покрыты полностью и общий оборот не ноль. Изменение для платформы считается, когда оба периода одной длины покрыты полностью, категории те же и предыдущий оборот не ноль. В остальных случаях показано «Сравнение недоступно». Для «Всё время» сравнения нет. Если скрыть платформу, карточки не меняются.

### Вкладки и mini-chart

Вкладка «Платформы» рисует две линии с общей шкалой USD. Вкладка «Категории» рисует stacked area выбранных категорий для включённых платформ. Столбцов нет.

Под графиком стоит mini-chart с ручками начала и конца периода. Ниже слева пресеты, справа экспорт. Колесо мыши меняет масштаб периода вокруг курсора. Перетаскивание мышью сдвигает период. Двойной клик возвращает последний выбранный пресет. Ручки mini-chart принимают стрелки, Shift с шагом в семь дней, Home и End.

Пока жест ещё идёт, preview в историю URL не пишется. Итог записывается в конце жеста. Масштаб колесом записывается с задержкой 300 мс. Горизонтальная сетка пунктирная.

### Выбор даты

На графике работают hover, перекрестие и выбор обеих платформ за одну дату. В режиме платформ подпись даты следует за курсором над графиком и остаётся внутри его границ. На узком экране недельный диапазон показан короче. Подписи значений сдвигаются по вертикали к выбранной точке. Числа берутся из данных, без промежуточных значений.

На тач-устройствах тап и горизонтальное перетаскивание выбирают дату. Вертикальный жест оставляет прокрутку страницы. Значения выбранной точки показаны на графике. С клавиатуры дату двигают стрелки влево и вправо, Home и End. Подписи сменяются сразу.

Цвета платформ фиксированы. Работают обе системные темы и reduced motion.

### Таблица категорий

Под графиком показаны 11 общих категорий за отображаемый диапазон. На десктопе это таблица, на телефоне список карточек. Сортировать можно по названию, обороту каждой платформы, общему обороту, доле и изменению к предыдущему периоду.

Сначала идут выбранные категории, затем невыбранные. Группы сортируются отдельно, включая «Другое». В каждой группе отсутствующие числа идут после известных. По умолчанию таблица отсортирована по убыванию общего оборота.

Суммы отдельных категорий от фильтра не зависят. Строка «Итого (выбранные)» считает только включённые категории. Фильтры меняются кнопками в блоке категорий. Клик по строке таблицы фильтр не меняет. Суммы на экране короткие, полное значение лежит в `title`. Отсутствующие значения показаны как «—». Полоса общего оборота делит его между Polymarket и Kalshi. На десктопе также показаны доли внутри платформ и мини-графики категорий.

## Конфигурация и API

Список переменных лежит в `.env.example`. Для режима Dune нужны `VITE_DUNE_API_BASE_URL`, read-only `VITE_DUNE_API_KEY` и два ID `VITE_DUNE_*_QUERY_ID`. Base URL в клиенте не зашит. Если конфигурации нет или она неверная, приложение на fixture не переключается. После правки `.env` перезапустите Vite.

`src/shared/api/api-service.ts` делает только HTTP GET. Он собирает параметры и заголовки, отменяет запрос и бросает `HttpError`. Наружу он отдаёт `unknown`. Адреса Dune и проверку ответов Zod делает `src/shared/api/dune/service.ts`. Общий транспорт и Dune-сервис не импортируют React, TanStack Query и IndexedDB.

## AI-анализ точки графика

Клик или тап без перетаскивания по графику платформ или категорий показывает аватар бота `clover` справа внизу. Наведение запускает его анимацию. Клик по боту открывает окно и сразу отправляет один платный запрос с фиксированным вопросом о событии периода. Сам выбор точки запрос не отправляет. Повторный клик по точке снимает или возвращает выбор. Окно закрывается крестиком. Кнопка «−» возвращает иконку бота.

С клавиатуры выберите точку стрелками и нажмите Enter. Hover и перетаскивание пальцем только выбирают дату. Перетаскивание мышью сдвигает период. Смена периода, категорий, платформ или данных сбрасывает выбор, чтобы в запрос не ушёл старый контекст. Поля ввода, продолжения диалога и истории переписки нет.

В локальный `.env` запишите `OPENROUTER_API_KEY` и перезапустите сервер. `.env` в Git не попадает. Пример переменной есть в `.env.example`. Префикс `VITE_` не ставьте. Ключ нужен только серверу и в браузерную сборку попасть не должен.

Браузер отправляет контекст на `/api/chart-analysis`. Сервер добавляет ключ, модель `perplexity/sonar`, фиксированный промпт и лимит ответа, затем отдаёт SSE без буфера. OpenRouter и Perplexity получают вопрос, точные даты UTC, оборот видимых серий в USD, активные категории и предыдущую точку на графике для сравнения. Пропуски уходят как `null`.

Endpoint подключён к `npm run dev` и `npm run preview` через `server/chart-analysis.ts`. Каталога `dist/` для этого запроса недостаточно. На хостинге нужен серверный endpoint. До публичного размещения закройте его авторизацией и лимитом запросов. Иначе чужие вызовы будут тратить общий ключ. Проверка Origin авторизацию не заменяет.

Sonar ищет главное событие выбранного периода и отвечает текстом от 3 до 5 предложений. Обороты он не пересказывает. Ответ идёт потоком SSE, текст появляется по мере получения.

Пока ответ не готов, аватар в состоянии `working` показывает «Ищем событие» или «Пишем ответ» и таймер. Ссылки вида [1] и [2] становятся короткими ссылками на домены. Полный список источников открывается отдельно. При reduced motion анимации выключены. После ответа текст можно скопировать и отправить платный повторный запрос.

Готовый ответ, вопрос, контекст, модель и время пишутся в `localStorage` по ключу `outpoll-chart-analysis-v1`. Если открыть ту же точку с теми же данными и фильтрами, подставится последний ответ и новый запрос не уйдёт. Ошибка записи ответ с экрана не убирает.

Оборванный или ошибочный поток остаётся на экране как неполный ответ и в хранилище не пишется. Старые ответы новый промпт не перезаписывает. Чтобы получить новый текст, нужен явный повтор. Закрытие окна отменяет ожидание в интерфейсе. Провайдер при этом всё равно может списать запрос.

Текст модели причинность не доказывает. Сверяйте его с источниками.

Код лежит в `src/features/chart-analysis/`. Там контекст и промпт, граница API с Zod, кэш в `localStorage`, mutation hook и панель одного запроса. Интерфейс анализа и Markdown загружаются при первом выборе точки для AI.

## Локальные fixtures

По умолчанию и в демо данные приходят из Dune, из живых результатов запросов. Режим fixture нужен для локальной разработки и вёрстки.

```sh
# Скачивает настоящие замороженные snapshots. Тратит кредиты Dune.
npm run fixtures:update

# Вёрстка без запросов к Dune.
VITE_DATA_MODE=fixture npm run dev
```

`src/shared/data/fixtures/kalshi-volume.json` и `polymarket-volume.json` хранят реальные полные snapshots. В файлах есть исходные категории, query ID, execution ID и время расчёта. JSON загружается лениво и только если режим fixture выбран явно. Файл проверяет Zod.

Этот режим IndexedDB не читает и не пишет. В интерфейсе отдельного значка режима нет. Режим задаёт конфигурация запуска. С Dune на fixture приложение само не переключается. Данные в файлах настоящие. Статичный режим нужен для разработки и требование ТЗ о живых данных не закрывает.

## Данные торгового оборота

Сырой JSON Dune проходит Zod и становится `SourceVolumeRow`, затем `VolumeSnapshot`. Экран берёт из snapshot строки `DashboardVolumeRow` и точки `ChartPoint`.

- `src/shared/api/dune/schemas.ts` и `types.ts` задают общий DTO обеих платформ. Туда входят числовые и десятичные строковые объёмы, проверка дат и metadata. Лишние поля конверта и metadata допускаются. Дата принимается как день ISO или полночь UTC и становится типом `Day`. Произвольный хвост строки и ненулевое время не принимаются.
- `src/shared/api/dune/service.ts` читает проверенные страницы через `ApiService`. Base URL берётся из конфигурации, туда же добавляется заголовок Dune. `client.ts` собирает snapshot по зафиксированному `executionId`, передаёт `AbortSignal` и проверяет число строк, непрерывность offset и неизменность metadata. SQL при этом не запускается. `next_uri` адресом следующего запроса не используется.
- `src/entities/volume/model.ts` задаёт `Day`, `Platform`, `SourceVolumeRow`, `VolumeSnapshot`, `DashboardVolumeRow` и `ChartPoint`. Snapshot хранит время расчёта, время скачивания и исходные категории. Таксономии в snapshot нет.
- `categories.ts` задаёт полный список известных категорий на этапе компиляции. Новая категория допустима и попадает в `other`. `mentions` пока тоже относится к `other`. Регистр учитывается только при сопоставлении. Исходное название категории не заменяется.
- `normalize.ts` переводит проверенный DTO в source row, затем в dashboard row.
- `src/entities/volume/select/selectors.ts` фильтрует по включённым категориям и по включительным границам `startDay` и `endDay`, затем суммирует по платформе и дню и сортирует. Диапазон 7, 30 или 90 дней сначала нужно превратить в границы UTC. Пустой выбор даёт `[]`. Если платформы за день нет, значение `null`. Подтверждённый день с нулевым отфильтрованным оборотом даёт `0`. Пропущенные календарные дни селектор не достраивает.
- `src/entities/volume/dashboard/dashboard.ts` превращает URL-фильтры в календарные диапазоны и недельную агрегацию для экрана. В отличие от селектора, он достраивает пропущенные календарные дни значением `null`, чтобы линия не соединяла пропуски. `src/entities/volume/lib/format.ts` задаёт формат дат UTC и сумм USD.
- `src/shared/storage/volume-cache.ts` пишет базу IndexedDB `outpoll-volume`, store `snapshots`, ключ `[platform, queryId]`. Запись атомарная. При чтении данные снова проходят Zod. Более старый расчёт более новый не перезаписывает.
- `src/entities/volume/data/repository.ts` соединяет контракт `VolumeDataSource` с кэшем уже загруженного snapshot. У Dune и fixture разные ключи запросов в памяти. В IndexedDB пишет только Dune.
- `src/entities/volume/data/queries.ts` отдаёт `volumeSnapshotQuery(repository, platform)` для `useQuery` и `fetchQuery`. `restoreVolumeSnapshot(queryClient, repository, platform)` читает кэш IndexedDB до подключения query. `src/main.tsx` восстанавливает обе платформы до первого рендера. Исходный `downloadedAt` становится `dataUpdatedAt`, поэтому старый snapshot не выглядит только что загруженным.
- `src/entities/volume/data/cache-config.ts` ставит volume queries `staleTime` в 60 минут. Snapshot старше семи дней не восстанавливается. Свежий snapshot показывается без HTTP. Допустимый старый snapshot показывается сразу, обновление идёт в фоне. Если обновление упало, остаются прежние данные, предупреждение и кнопка повтора. Запросы fixture статичные, у них `staleTime: Infinity`.

После восстановления подключайте query через `useQuery(volumeSnapshotQuery(repository, platform))`. Новый snapshot пишется только после успешной загрузки всего результата. Неудачное обновление оставляет предыдущий snapshot в IndexedDB. Сопоставление категорий и фильтрация идут локально. Новых запросов они не делают и в постоянный кэш не пишутся. Пустой выбор, отсутствие данных и ошибку запроса интерфейс показывает отдельно.

Ключ Dune, который попал в браузер, виден этому пользователю. Для локального демо берите только ограниченный read-only ключ. Ключ с лишними правами в репозиторий и в клиентскую production-сборку не кладите. Чтение готового результата SQL не запускает, но тратит кредиты Dune.

Тесты подставляют свои ответы только на границе внешнего API. Транзакции IndexedDB проверяет `fake-indexeddb`. В интерфейс вымышленные рыночные данные не добавляются.

## Дизайн

Шрифты локальные, через Fontsource.

- Geist Sans, класс `font-sans`, для текста и заголовков.
- Geist Mono, класс `font-mono tabular-nums`, для цифр.
- Geist Pixel, класс `font-logo`, только для логотипа.

Пока тему не выбрали вручную, она следует `prefers-color-scheme`. Кнопка в шапке переключает светлую и тёмную тему и пишет выбор в `localStorage`. Общий акцент фиксирован. Это фиолетовый `#5016ff` для основных действий. Настройки акцента нет. Синий Polymarket и зелёный Kalshi остаются на графике и в карточках оборота.

Базовые компоненты ставятся из shadcn/ui и лежат в `src/shared/ui/`. Сейчас в проекте используются Button, Popover, Toggle, ToggleGroup, Card, Table, Skeleton, Empty, Alert, Spinner, Avatar, Collapsible, Dialog, Progress, ScrollArea, Tabs и Tooltip. `components.json` задаёт Base UI, стиль `base-nova`, Tailwind v4 и алиасы `@/shared/ui` и `@/shared/ui/utils`. Новый компонент добавляйте командой `npx shadcn@latest add <component>`. Свои кнопки, меню, popover и переключатели не пишите. Для `cn()` берите `src/shared/ui/utils.ts`. Если CLI сгенерирует импорт из `cn`, замените его на этот алиас.

Токены, базовые стили и правила SVG для графика лежат в `src/styles.css`. Файл подключает Tailwind, `tw-animate-css` и `shadcn/tailwind.css`. Токены shadcn `primary`, `card`, `popover`, `muted`, `accent`, `input` и `ring` связаны с палитрой Outpoll. Вариант `dark:` читает атрибут `data-theme`. Атрибут выставляется до первого рендера React.

Приглушённый текст задавайте классом `text-muted-foreground`, приглушённую поверхность классом `bg-muted`. Отдельные оттенки в компонентах не задавайте. Раскладку задавайте утилитами Tailwind, без отдельных CSS-классов для кнопок и popover.

Композиция следует [Vercel design.md](https://vercel.com/design.md) в общих краях, сетке на 4, 6 и 12 колонок и интервалах. Интервал между элементами задаёт родитель через `gap`. Компоненты берутся из shadcn, шрифты из семейства Geist.

Шаг шкалы Tailwind равен 4px. В проекте заданы `gap-group` на 12px, `gap-section` от 48px до 64px, `px-page-gutter` от 24px до 32px, `max-w-page` на 1536px, `max-w-reading` на 65ch, `text-page-title` и `text-section-title`. Оболочка страницы сейчас использует `px-2`, то есть 8px.

Клавиатуру базовых контролов даёт Base UI. У графика и mini-chart свои обработчики клавиш. Денежные значения используют табличные цифры. Анимации shadcn выключаются при reduced motion. Цвета линий задают `--platform-kalshi` и `--platform-polymarket`. От фиолетового акцента они не зависят.
